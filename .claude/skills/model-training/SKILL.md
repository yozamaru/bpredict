# モデルの学習と評価

パラメータと採用基準の実体は `docs/design-detail.md` 4.5〜4.7 にある。**このスキルは判断基準と禁止事項を扱う。**

## モデル構成

| モデル | 出力 |
|---|---|
| Winner | ホーム勝利確率（**経路A**） |
| Margin | 得点差（ホーム − アウェイ）。残差 σ から勝率も導出する（**経路B**） |
| Total | 合計得点 |
| TeamRates | チームの試投数・成功率・その他カウント（14項目）。**整合化の目標値** |
| PlayerAvail | 選手の出場確率 |
| PlayerMinutes | 出場時間（出場する場合） |
| PlayerRates | カウント11項目の単位時間レート + 成功率3項目 |

### 勝率は2経路とも実装する

| 経路 | 式 | 長所 | 短所 |
|---|---|---|---|
| A: Winner 直接 | `p = Winner(x)` | logloss を直接最適化するため較正が良い | Margin と符号が食い違いうる |
| B: Margin から導出 | `p = Φ(margin / σ)`、σ は残差標準偏差（実測） | 勝率と予想スコアが定義上一致する | 残差が正規でない場合に較正が崩れる |

同一の walk-forward ウィンドウで Brier と ECE を測り、**B が A より Brier で 0.003 以上劣る場合のみ A を採用する**。どちらかだけを勝手に実装しない。採用経路は `model_versions.win_prob_source` に記録する。

### 予想スコアは Margin と Total から導出する

```
home = (total + margin) / 2
away = (total - margin) / 2
```

**各チーム得点を独立に回帰しない。** 勝率68%なのに「82–85でアウェイ勝ち」という出力が原理的に起こり、接戦ではほぼ確実に発生する。試合詳細画面で勝率とスコアが並ぶため**ユーザーに直接見える**。また独立回帰は得点差の分散も過大にする（ホーム得点とアウェイ得点はペース経由で強く正相関する）。

分類器を残す場合も、`home_win_prob > 0.5` と `pred_home_score > pred_away_score` の符号一致をアサーションで検証する。

### 個人スタッツは4段構成

```
第1段  PlayerAvail    P(出場)                          二値分類
第2段  PlayerMinutes  E[出場時間 | 出場]               回帰
第3段  PlayerRates    カウント11項目: 単位時間レート   回帰 × 11
                      成功率3項目: 2FG%/3FG%/FT%       回帰 × 3（per-minute にしない）
第4段  Reconciliation チーム予測への整合化             計算
```

予測する14項目:

- **カウント11**: `fg2a, fg3a, fta, oreb, dreb, ast, tov, stl, blk, pf, fd`
- **成功率3**: `fg2_pct, fg3_pct, ft_pct`

**シュートは「試投数 + 成功率」で予測し、成功数は導出する。** 成功数と試投数を別々に予測すると、整合化で両者を独立にスケールすることになり、`成功数 > 試投数` を防ぐクリップが収束を壊す。実測では失敗ケースの **73% が FT 成功率**で発生した。試投数と成功率の組なら、成功率をロジット空間でシフトするだけで制約が自動的に満たされる。

**モデルが出す成功率を画面にそのまま出さない。** これは「この選手のこの試合における期待成功率」という連続量であり、表示する `FGM / FGA` とは別物である。1試合の試投数は6本程度で、実績としての FG% は7通りの離散値しか取りえない。表示は必ず分数と併記し、試投数が閾値未満なら率を出さない。

**PTS・FGM・FGA・TR・成功数を独立に予測しない。** 恒等式で導出する。

```
2FGM = 2FG% × 2FGA,  3FGM = 3FG% × 3FGA,  FTM = FT% × FTA
PTS  = 2FGM × 2 + 3FGM × 3 + FTM
FGM  = 2FGM + 3FGM,  FGA = 2FGA + 3FGA,  TR = OR + DR
```

FG を予測してから 2P/3P に分解すると `FGM = 2FGM + 3FGM` が成立しない。**2P と 3P を予測して合計を取る向き**にする。

**＋/－ を予測しない。** チームの結果を個人に帰属させた指標で、1試合の分散が極端に大きく MAE は 9〜12点規模になる。しかも「チーム得点差予測 × 出場時間シェア」以上の情報を持たないため、出しても新しいことを伝えない。実績のみ表示する。EFF も同様（複数項目の誤差が合算される）。

**カウント11項目は per-minute で学習する。** カウントをそのまま学習すると出場時間の分散に支配され、出場時間の予測誤差がそのまま全項目に伝播する。

**成功率3項目は per-minute にしない。** 率は時間当たりの量ではないため per-minute 化は無意味である。目的変数はシュリンク済み成功率（`(made + k × prior) / (att + k)`、prior はリーグ平均）、学習重みは試投数、出力は `clip(0.01, 0.99)`（ロジット変換の定義域確保）。

`P(出場) < 0.5` の選手は表示対象から除外する。登録選手の3〜4割が0分であり、単一回帰では欠場濃厚な選手に「8分・4.2点」のような値が出る。

期待値の積（`E[minutes] × E[pts/min]`）は `E[minutes × pts/min]` と等しくない。出場時間と単位時間生産性は正相関するため素朴な積は過小評価になる。第4段の整合化で補正する。

### 整合化（第4段）を省略しない

**選手ごとに独立予測した値をそのまま保存・表示してはならない。** 5人の得点合計がチームの予想スコアと一致せず、FGA の合計もチーム予測とずれる。同じ画面に矛盾した数字が並ぶ。

手順は `docs/design-detail.md` 2.4 にある。要点は次の6つ。

1. 期待出場時間 `m_i = P(出場_i) × E[MIN_i | 出場]`
2. 総出場時間を 200分（5人 × 40分）に正規化
3. 試投数・その他カウント `x_i,s = rate_i,s × m_i`
4. 試投数・その他をチーム目標へ比例スケール
5. **成功率をロジット空間で一律シフト**し `Σ(pct_i × att_i) = チーム成功数` を満たす `d` を `brentq` で解く
6. 得点・成功数は恒等式で導出

**手順5でクリップを使ってはならない。** 成功率を `[0,1]` の範囲で一律に掛け算すると、1.0 に張り付いた選手が出た時点で合計を目標に合わせられなくなり振動する。ロジットは `(0,1)` を `(-∞,∞)` に写すためクリップが原理的に不要で、単調性から解が一意に存在する。

```python
def shift_to_target(pct, att, target):
    lo = logit(np.clip(pct, 1e-4, 1 - 1e-4))
    f  = lambda d: (sigmoid(lo + d) * att).sum() - target
    return sigmoid(lo + brentq(f, -50, 50))
```

**反復は3回。** 実測（1,500ケース）で項目誤差の99%点が 0.27%、最大 1.87%、得点誤差は厳密にゼロ。旧版の倍率スケール2回反復は収束せず、項目誤差の最大 24.7%・得点誤差 4.42点だった。

**チーム側の目標値も「試投数 + 成功率」で持つ。** 各項目を独立に生成すると約2%の確率で `FT成功数 > FT試投数` という実行不能な目標が生まれ、整合化が原理的に成立しない。TeamRates モデルがこの構造で出す。

**TeamRates の生出力をチーム目標にしない。前段の整合化を挟む。** TeamRates と Margin / Total は別モデルであり、TeamRates から導出した得点が予想スコアと一致する保証がない。そのまま選手側へ渡すと「選手の合計＝チーム目標」は満たされても「チーム目標＝画面に出る予想スコア」が崩れ、矛盾の位置が一段ずれるだけになる。

```
pts(d) = 2*sigmoid(l2+d)*A2 + 3*sigmoid(l3+d)*A3 + 1*sigmoid(lf+d)*Af
pts(d) = (total ± margin) / 2 を満たす共通シフト量 d を brentq で解く
```

- 予想スコア（Margin / Total 由来）を**正**とし、チームの成功率3項目を寄せる
- **試投数は動かさない。** ペースと配分の予測はそのまま残す
- `sigmoid` は単調増加、係数（2/3/1）と試投数は非負なので **解は一意。反復は不要**
- 値域 `(0, 2*A2 + 3*A3 + Af)` の外は到達不能 → `InfeasibleTargetError`
- 実装は `reconcile_team_targets()`（`docs/design-detail.md` 2.4 前段）

この前段を通した値だけを `prediction_team_targets` に保存する。学習段階で予想スコアに合わせ込まない（合わせ込むのは推論時）。

**実行不能な目標に出会ったら例外を投げる。** 無言でクリップして辻褄を合わせない。当該試合の個人スタッツ予測を破棄し、画面に算出不能と表示する。

予測時点で延長戦を仮定しない（総出場時間は常に200分）。

許容誤差は**得点 ±0.5点、その他 ±2%、制約違反0件**。

> 検証スクリプト: `verification/03_reconciliation_logit.py`

### 低レート項目の扱い

ST と BS は1試合あたり平均0.7回程度で、**MAE が平均値と同水準**になる。これは実質「その選手の平均を出しているだけ」であり、予測としての付加価値がほとんどない。

表示はするが、これを隠さず誤差目安を併記する。学習時間が枠に収まらない場合、この2項目を「直近平均の表示」に代替してよい。その場合は画面に「この項目は直近平均を表示しています」と明示し、**予測と称して平均を出さない**。

### 学習コストの管理

選手モデル16本（カウント11 + 成功率3 + 出場2）とチームモデル14本の学習が必要で、選手スタッツの学習行数は約20万行ある。

- `monthly_train` のタイムアウトは120分
- **選手モデルの fold 数は3に制限する**（チームモデルは5）
- 収まらない場合の対処順: 木を小さくする → 学習行数を直近5シーズンに制限 → 低レート項目をモデルから外す

`model_versions` は `(model_type, target, league)` で有効モデルを一意にする。`PLAYER_RATE` と `TEAM_RATE` はそれぞれ14本あるため、`target` を含めないと部分ユニークインデックスが衝突する。

推論に使ったモデル一式は `prediction_model_bundle` に記録する。`predictions.model_version` はチームモデルしか指せず、個人スタッツがどのモデルで出たかを復元できない。

## 検証方式

**シーズン単位の walk-forward のみ。入れ子の分割にする。**

```
fold i:  train = seasons[:i-1]
         valid = seasons[i-1]     ← early stopping 用
         test  = seasons[i]       ← 一切触れない
```

```python
train_test_split(X, y, shuffle=True)    # 禁止
KFold(shuffle=True)                     # 禁止
```

`train_lightgbm(X, y)` のように検証セットなしで early stopping を書かない。学習データを渡せば止まらず（過学習）、評価シーズンを渡せばリークする。

**fold 数に上限を設ける**（直近5シーズン）。設けないとシーズンが増えるたびに学習時間が単調増加し、5年後に破綻する。

最終モデルは各 fold の `best_iteration` の中央値を `num_boost_round` に固定し、early stopping なしで学習する。

## 再現性

`seed` / `bagging_seed` / `feature_fraction_seed` / `deterministic` を固定し、`model_versions.params` に記録する。

固定しないと `bagging_fraction=0.8` により **Brier が ±0.003 ぶれる**。採用基準が「現行以下」である以上、**モデルの差し替え可否が実質的に乱数で決まる**。「先週より良いから差し替える」という運用が、実態としてはランダムウォークになる。

CI で「同じ入力・同じ seed の2モデルの予測が完全一致すること」を検証する。

## 確率較正

**較正は out-of-fold で fit する。** 学習データそのもので fit すると、学習データ上の過剰な分離を「正しい」と学習し、本番では過信が**増幅**される。しかも較正誤差は in-sample では小さく見えるため、採用ゲートも機能しなくなる。

**そもそも必要かを先に測る。** logloss を目的関数にした LightGBM の出力は元々ほぼ較正されている（「二値分類の出力は極端に寄る」のは SVM・Naive Bayes・RandomForest の性質）。較正なしの信頼性曲線を測り、ECE が十分小さければ較正器を入れない。

入れる場合、**Platt scaling（パラメータ2個）を第一候補**とする。Isotonic は自由度が高く、n=800 程度では裾のブロックが数サンプルになり悪化しうる。使う場合は `out_of_bounds="clip"` と最小ブロックサイズを必須にする。

較正器も `model_versions` の管理対象に含める。

## ベースライン

**3段で持つ。**

1. ホームチームが必ず勝つ（Accuracy の比較用。約60%）
2. **`elo_diff` 単体のロジスティック回帰**（GBDT の真の対抗馬。Brier 0.213〜0.220 程度）
3. 全特徴のロジスティック回帰

**2 を Brier で有意に上回れなければ、LightGBM を使う理由がない。** スポーツの勝敗予測では、GBDT が Elo 単体を有意に上回らないことが珍しくない。

## 評価指標

| 指標 | 役割 |
|---|---|
| Brier Score | **主要な改善指標** |
| ECE（等頻度10ビン、ビンあたり最低50） | 較正誤差。**閾値は n 依存のノイズフロア基準**。n < 500 では使わない |
| Accuracy | **表示専用。採用ゲート・モデル比較・アラートのいずれにも使わない** |
| Log Loss | 学習時の目的関数 |
| MAE | 予想スコアの誤差 |

**Accuracy をゲートにしない理由**: ホーム勝率60%の下では、良い確率モデルでも `home_prob > 0.5` を出す試合が大多数になるため Accuracy はベースラインとほぼ並ぶ（62〜66%）。Brier で明確に優れているモデルが Accuracy 条件で誤って棄却される。

**ECE の閾値を固定値にしない（検証済み）。** 完全に較正されたモデルでも、ECE はサンプリングノイズだけで有限の値を取り、その大きさは n に強く依存する。4,000回シミュレーションの実測:

| n | 1ビンの件数 | ECE 平均 | ECE 95%点 | 固定閾値 0.05 の挙動 |
|---|---|---|---|---|
| 200 | 20 | 0.0824 | 0.1163 | **完全なモデルでも落ちる** |
| 500 | 50 | 0.0518 | 0.0734 | 半々 |
| 1,200 | 120 | 0.0337 | 0.0479 | **ほぼ常に通過** |
| 3,000 | 300 | 0.0212 | 0.0299 | 常に通過 |

- **n < 500 では ECE をゲートに使わない**（1ビン50件を満たさない）
- **n ≥ 500 では `ECE < ノイズフロア95%点 × 1.5`**。フロアはモデル自身の予測確率分布からブートストラップで毎回推定する。上表は一様分布での参考値であり、定数化しない

> 検証スクリプト: `verification/01_ece_noise_floor.py`

## 採用基準

```python
MIN_EVAL_N  = 500      # これ未満では一切比較しない
MIN_EFFECT  = 0.003    # 最小実質差（Brier）
ECE_FLOOR_K = 1.5

def passes_criteria(m, model) -> bool:
    if m.n < MIN_EVAL_N:
        log("n < 500 のため比較せず現行モデルを継続", n=m.n)
        return False
    current = current_active_brier_on_same_window()
    return (m.brier < current
            and m.brier_diff_ci_upper < 0            # 有意差
            and (current - m.brier) >= MIN_EFFECT    # 実質差
            and m.brier < m.baseline_elo_brier
            and m.ece < ece_noise_floor(m.pred_probs, m.n, q=0.95) * ECE_FLOOR_K
            and max(m.feature_null_rates.values()) <= 0.30)
```

**`n < 500` では比較そのものを行わない。** 理想モデル（真の勝率を知る上限）とベースラインの Accuracy 差の SD は n=200 で 0.041、n=500 で 0.026。旧基準の `accuracy - baseline >= 0.03` は n=200 では 1SD 以内で、**理想モデルですら 8.5% の確率で落ちる**。

| n | 理想モデル | ベースライン | 差の平均 | 差の SD | `+0.03` を落ちる確率 |
|---|---|---|---|---|---|
| 200 | 0.656 | 0.572 | 0.085 | 0.041 | 8.5% |
| 500 | 0.656 | 0.572 | 0.084 | 0.026 | 1.7% |
| 1,200 | 0.656 | 0.571 | 0.085 | 0.017 | 0.0% |

**月次再学習の検出力は低いが、ゲートを緩めない。** 真の差 0.03 を検出できる確率は n=200 で 12.7%、n=1,200 でも 54.8%。上記のゲートは「ノイズで誤って差し替える」ことを防ぐ側に倒してあり、その代償として「実際の改善を見逃す」。見逃した改善は次回以降の月次で拾う。**検出力を上げるために閾値を下げるのは、誤差し替えを招く方向の変更である。**

> 検証スクリプト: `verification/02_acceptance_criteria_power.py`

**比較は同一の評価ウィンドウで行う。** `model_versions.cv_brier`（学習当時の値）を直接比較しない。新旧で検証対象のシーズンが違えば比較になっていない。

`current_active_brier_on_same_window()` は、`GET /internal/metrics/active` で現行モデルの識別子を得て、`GET /internal/models/:version/artifact` でその artifact を取得し、**新しい評価ウィンドウで再評価した値**を返す。API が返す `cvBrier` はログ突き合わせ用であり、比較には使わない。

**有意差を要求する。** 検証800試合での Brier の標準誤差は約0.009、対応ありの差でも0.003〜0.005ある。0.1860 vs 0.1859 で差し替えると、ノイズで毎週入れ替わり精度推移がギザギザになる。逆に偶然良い値が一度記録されると、以後それを下回れず**新モデルが永久に有効化されないロックイン**に入る。

**基準を満たさない場合、新モデルを有効化しない。** 現行を使い続け、ログに理由を残す。「前より少し良さそうだから」で差し替えない。

## パラメータ

```python
"num_leaves": 7, "max_depth": 3, "min_data_in_leaf": 100
```

```python
"num_boost_round": 1200    # 上限。artifact サイズが 1.5MB を超えないための制約でもある
```

試合数は約8,000件しかない。**木を深くせず、正則化を効かせる。** この問題の信号量（Elo差だけで Brier 0.215 程度、上限でも 0.20 前後）に対し、深さ5・葉15は5次の交互作用を許す設定で過大である。

精度が出ないときに `num_leaves` や `max_depth` を上げない。まず特徴量を見直す。探索は時系列 CV 上で小さめのグリッドを回す。

**`num_leaves` を 15 にする変更は、artifact サイズの再測定とセットでのみ行う。** `num_leaves=15` / 木1,500本では推定 2.56MB となり、D1 の1行上限（2,000,000バイト）を超える。登録時のサイズガードが拒否するため事故にはならないが、探索範囲に 15 があるからという理由で無自覚に踏まないこと。

## 分布シフト

全シーズンを一様に扱わない。

- **観客制限期間（2020-21 / 2021-22、約1,500〜2,000試合）**: この期間はホームアドバンテージ自体が消失する。Elo 更新時の `HOME_ADVANTAGE` を0にし、動員系特徴の集計から除外する
- **時間減衰**: `weight = exp(-λ × 経過シーズン数)`。半減期3〜5シーズンが出発点。λ は walk-forward で探索する
- **昇格クラブ**: Elo 1500（＝旧B1平均）を与えない。大幅に過大評価する。リーグ間オフセットを推定するか、前季下位層の水準にする

## Elo のパラメータ

`K`、`HOME_ADVANTAGE`、シーズン間回帰率は**実データで探索する**。NBA 実装からの転用値をそのまま使わない。NBA（82試合）と Bリーグ（約60試合）ではシーズン長が異なり、最適値が変わる。

チーム別ホームアドバンテージは**階層モデル（部分プーリング）にする**。1チームあたりのホーム試合は年約30試合で、ホーム勝率の標準誤差は約9ポイント。見かけの差の大半はノイズであり、素朴な推定は序盤にホーム連勝したチームの予測を過大にする。

## モデルの保管

**LightGBM の `save_model()` 出力を `model_versions.artifact_text` として D1 に格納する。**

GitHub Actions の artifact はデフォルト90日で失効し、別ワークフローから取得するには run-id 解決が必要なため、日次推論の依存先として成立しない。放置すると**90日後に静かに推論が止まり、縮退したまま永久に回復しない**。

リポジトリにコミットしない。

**登録と読み出しは Workers 経由で行う。** 学習ジョブは `POST /internal/models` で登録し、日次推論は `GET /internal/models/active`（メタのみ）→ `GET /internal/models/:version/artifact`（本体を1本ずつ）で取得する。**バッチが D1 を直接読み書きしない。D1 REST API も叩かない。** 有効モデルは最大33本あり1本あたり最大1.5MB になるため、一覧に artifact 本体を載せない。

**登録前に 1.5MB の上限を検査する。** D1 の1行上限は 2,000,000 バイト。書式からの推定:

| `num_leaves` | 木の本数 | 推定サイズ | 上限に対して |
|---|---|---|---|
| **7（設計値）** | 300〜800 | **0.27〜0.70 MB** | 13〜35% |
| 7 | 2,000 | 1.75 MB | 88%（危険域） |
| 15 | 1,500 | 2.56 MB | **128%（超過）** |

超えた場合は**登録せず現行モデルを継続使用し、`exit 1` で終える**。実サイズは Phase 0（P0-12）で測定する。

> 検証スクリプト: `verification/04_artifact_size_and_batch_limits.py`

## 学習入力

**学習・特徴量生成は D1 を読まない。** 入力は `batch/snapshot/*.parquet` のみ。学習前に `MANIFEST.json` の行数と SHA256 を照合し、不一致なら学習を中止する。`test_training_reads_no_d1` で D1 クライアントが呼ばれないことを検証する。

## ロールバック

```sql
UPDATE model_versions SET is_active = 0
 WHERE model_type = 'WINNER' AND target = '' AND league = 'PREMIER';
UPDATE model_versions SET is_active = 1 WHERE version = 'winner-v1.0.0';
```

`uq_model_active`（部分ユニークインデックス）により、この順序でのみ成功する。手順書ではなく DB 制約で守る。確定済み予測（`is_final = 1`）は変更しない。

## 根拠の抽出

- SHAP 値は**ログオッズ空間**であり確率への加算ではない。`%` で表示しない
- **個別特徴ではなく要因グループ（チーム力 / 日程・疲労 / 選手 / 会場）に集約する。** 相互相関0.6〜0.9のため、個別のままだとほぼ同じ条件の2試合で表示される根拠が入れ替わる
- 符号は「ホーム有利が正」に統一し、`favors` で有利な側を明示する
- `base_value` を保存し、事後検証を可能にする
- `explainer` は推論ループの外で1回だけ構築する
- **選手個人の能力・資質への評価を含む表現を使わない**（可:「出場時間の減少」/ 不可:「不調」「衰え」）
- 動員が上位に来ても因果として表示しない（強さの代理変数）

## 回帰テスト

- `feature_list` の新旧差分と各特徴量の欠損率をログ出力する
- 保存済み `feature_snapshot` から代表100試合を固定サンプルとし、新モデルで再推論して `|p_new - p_old| > 0.15` が10件を超えたら失敗させる

## やってはいけないこと

- ランダムシャッフルでの検証
- 検証セットなしの early stopping
- 乱数シードを固定しない学習
- 学習データでの較正
- Accuracy を採用ゲート・モデル比較・アラートに使うこと
- `n < 500` での比較・差し替え
- ECE の閾値を固定値（0.05 など）にすること
- `cv_brier` の直接比較（評価ウィンドウが異なる）
- 有意差なし、または実質差 0.003 未満でのモデル差し替え
- 検出力を上げるために採用基準を緩めること
- 確定済み予測の書き換え
- 精度が出ないときの木の深さ増加
- モデルバイナリのコミット
- 75%超の的中率を成果として受け入れること
- **シュートの成功数を試投数と別々に予測すること**（試投数 + 成功率で持つ）
- **モデルが出す成功率を画面にそのまま出すこと**（表示は `FGM / FGA` の導出値で、分数と併記）
- **PTS / FGM / FGA / TR / 成功数 を恒等式ではなく独立に予測すること**
- **＋/－ や EFF を予測すること**
- **整合化を省いて選手予測をそのまま保存すること**
- **整合化でクリップを使うこと**（ロジット空間シフトを使う）
- **実行不能なチーム目標を無言でクリップして辻褄を合わせること**（例外を投げる）
- カウント項目を per-minute にせず学習すること
- 成功率項目を per-minute で学習すること
- 勝率の導出経路を比較せずどちらか一方だけ実装すること
- 学習で D1 を読むこと
- 低レート項目の代替値を「予測」と称して表示すること
