## backfill は AI が実行する（2026-09-25 から）

運営者の指示により、`gh workflow run` で AI が起動する。**守ること。**

- **1日の書き込み見積りを 92,000行に収める**（枠は10万行で 00:00 UTC にリセット）。
  シーズン単位ではなく行数で管理する — 「1日1シーズン」だと毎日34%を捨てる
  - 1試合 ≈ **118.6行**、1シーズン ≈ **65,800行**（実測）
  - 当日の消費 = 当日UTC の `ingestion_logs`（`job='backfill'`）の `rows_affected` 合計 × 118.6
  - 端数のシーズンは `-f limit=floor((92000 − 消費 − 200) / 118.6)` で起動する
  - **1日の起動は最大2回**（1シーズン ＋ 端数）。3回以上に分けると日程29ページの取り直しが増える。
    ただし**取りこぼしを拾う再実行（数試合）はこの数に入れない**（日程29ページ＋数件で済む）
- **実行前に宣言し、枠と本日の実行履歴を確認する**
- **規約 / robots が変わったら絶対に承認せず、止めて報告する。** 承認は運営者のみ
- ログは `gh run view <id> --log` で AI が読む（スクリーンショットは不要）

`gh` は `yozamaru` として認証済み（スコープ `repo`）。Variables の読み書きもできる。
**Secrets は読めない**（設計どおり）。

`verification/RESULTS.md` に詳細がある。**同じ罠を二度踏まないために、ここには見出しだけ置く。**

- 内部APIへのリクエストは **User-Agent を送る**（urllib の既定は Cloudflare が 403 で弾く）
- **1シーズンの D1 書き込みは約65,800行 / 1試合 118.6行**（設計の見積り26,500行は外れていた）。上限はシーズン数ではなく行数（詳細設計 4.8）
- 公式サイトから 429/503 を受けたら、クライアントがそのUTC日の取得を自動停止する。**朝（09:00 JST）まで待つ**
- D1 は `PRAGMA foreign_keys=OFF` を無視する。**データが入ったままでは参照されているテーブルを作り直せない**
- **workers.dev のサブドメインを変えると旧URLは NXDOMAIN になる**（リダイレクトされない）。
  `API_BASE_URL` の Variable と `docs/STATUS.md` を同時に直す。新URLの TLS 証明書は
  変更直後は出ておらず、`sslv3 alert handshake failure` になる（数分〜数十分で解消する）
- **日程の行は全部が `<a>` ではない。** 中止・延期の行はリンクを持たず、状態欄が
  `<script>` だけの行もある（2018-19 の CS）。1件で**シーズン全体が落ちた**。詳細設計 4.4
- **行のクラブ名は略称のことがある**（2020-21 の `千葉J` / `横浜BC`）。名前で絞ると
  実在の試合を落とす（120試合）。**判定は公式の `TeamID` で行う**（要件 5.3）
- **飛ばした行の counter を理由ごとに分ける。** 混ぜると原因の切り分けに実サイトへの
  再取得が要る。さらに**行単位で数えると CS が二重計上される**（`event=2` と
  `event=3` の両方に出るため。128行 = 120試合 + CS 8行）
- 公式サイトは**たまに 502 を返す**（`ResponseError`）。2018-19 では555試合中11件。**1試合の失敗ではジョブを止めず、飛ばして続ける**（連続3件で中止）。再実行で拾う
